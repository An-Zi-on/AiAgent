# Spring AI Embedding 模型选型指南

## Embedding 模型的作用

Embedding 模型负责把文本映射为固定维度的稠密向量。语义相近的文本在向量空间中距离更近，因此可以通过向量相似度来衡量文本之间的语义相关性。RAG 的检索质量在很大程度上取决于 Embedding 模型的效果。

## 常见选型维度

选择 Embedding 模型时，通常需要考虑以下因素：

- **语言支持**：中文场景应优先选择对中文优化过的模型，例如通义千问的 text-embedding 系列、智谱的 Embedding-3、BGE 系列等。
- **向量维度**：维度越高表达能力越强，但存储和计算成本也越高。常见维度为 768、1024、1536。
- **最大输入长度**：决定单个文本片段可以有多长，常见为 512 到 8192 token。
- **计费方式**：多数云端模型按 token 计费，本地模型则无 API 费用但需要算力。
- **接口兼容性**：是否兼容 OpenAI Embedding 接口规范，直接影响迁移成本。

## 云端与本地方案对比

**云端 API 方案**：接入简单，无需本地算力，适合快速验证和中小规模应用。代表平台包括阿里云百炼、智谱 AI、硅基流动等。需要注意账户余额、限流和网络依赖。

**本地部署方案**：通过 Ollama 等工具在本地运行开源模型，例如 nomic-embed-text、bge-m3。数据不出本地，无 API 费用，但需要一定的硬件资源，且模型效果可能不如大型云端模型。

## 在 Spring AI 中切换模型

Spring AI 通过统一的 EmbeddingModel 接口屏蔽底层差异。使用 OpenAI 兼容接口时，只需调整配置中的 base-url、api-key 和 model 三项，业务代码无需改动。这也是优先选择兼容 OpenAI 规范的平台的原因。
