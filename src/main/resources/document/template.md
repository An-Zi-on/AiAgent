# RAG（检索增强生成）知识库

## 1. 概述

**检索增强生成（Retrieval-Augmented Generation, RAG）** 是一种将外部知识检索与大语言模型生成相结合的技术框架。其核心思想是：在模型生成回答之前，先从外部知识库中检索与用户查询相关的文档片段，将这些片段作为上下文提供给模型，使生成结果基于可验证的外部证据，而非仅依赖模型训练时固化的参数化知识。

RAG 的设计初衷是解决大语言模型的三个固有问题：**幻觉**（生成看似合理但事实错误的内容）、**知识陈旧**（训练数据存在截止日期）、**领域适应不足**（缺乏企业私有或专业领域知识）。通过引入非参数化的外部记忆，RAG 使模型能够在推理时动态获取最新、最相关的信息，而无需重新训练模型。


## 2. 核心架构与工作流程

RAG 系统通常遵循三个基本阶段：**索引（Ingestion）**、**检索（Retrieval）**、**生成（Generation）**。微软的文档将其概括为"查询嵌入 → 检索 → 生成"的三步模式。

### 2.1 索引阶段（离线）

在用户发起查询之前，知识库需要预先处理。流程如下：

1. **数据提取与清洗**：从源文档（PDF、Word、网页、数据库等）中提取纯文本，去除页眉页脚、特殊字符等噪声。
2. **文本分块（Chunking）**：将长文档切分为较小的、可独立检索的片段。分块大小是关键设计决策：小块产生更精确的嵌入，但数量更多、存储与计算开销更大；大块保留更多上下文，但可能引入无关信息。常见策略包括按句子、段落或固定 token 数切分，并可设置重叠窗口以保持跨块连续性。
3. **嵌入（Embedding）**：使用嵌入模型将每个文本块转换为高维向量，使语义相似的文本在向量空间中距离相近。
4. **存储与索引**：将向量存入向量数据库（如 pgvector、FAISS、Chroma 等），并建立近似最近邻（ANN）索引以支持快速检索。同时，需将元数据（源文档标题、页码、章节等）与向量关联存储，以便生成阶段提供引用溯源。

### 2.2 检索阶段（在线）

1. **查询嵌入**：用户输入问题后，使用与索引阶段**相同的嵌入模型**将查询转换为向量。
2. **相似度搜索**：在向量数据库中检索与查询向量最相似的 top-k 个文本块。检索质量直接决定生成质量：返回不相关内容会导致模型产生错误回答，遗漏相关内容则使答案不完整。
3. **可选优化**：高级 RAG 系统可能加入重排序（Re-ranking）、混合检索（稀疏+稠密）、元数据过滤等步骤以提升召回精度。

### 2.3 生成阶段

将检索到的文本块与原始用户问题组合成一个**增强提示**，提交给大语言模型。模型基于这些上下文生成回答。提示中通常包含指令，要求模型仅依据提供的上下文作答，并在适当位置标注引用来源。


## 3. 关键设计参数

| 参数 | 说明 | 影响 |
|------|------|------|
| **分块大小** | 每个文本块的 token 数或字符数 | 小块检索精度高但碎片化；大块上下文完整但噪声多 |
| **分块重叠** | 相邻块之间的重叠 token 数 | 防止关键信息被切分边界截断，但增加索引冗余 |
| **检索数量（top-k）** | 返回给模型的文本块数量 | k 越大上下文越丰富，但可能引入低相关内容，增加 token 成本 |
| **嵌入模型** | 将文本转为向量的模型 | 通用小模型快且便宜；领域微调模型在专业场景下检索性能更优 |
| **温度（Temperature）** | 控制生成随机性 | 低于 1 更确定，高于 1 更随机。RAG 场景通常使用较低温度以提高事实一致性 |


## 4. RAG 的优势与局限

### 优势

- **减少幻觉**：生成基于检索到的证据，回答可溯源至具体文档片段。
- **知识可更新**：修改知识库索引即可更新系统知识，无需重新训练模型。
- **领域适应**：接入企业私有文档即可回答专业问题，成本远低于微调。
- **可解释性**：通过返回引文元数据，用户可验证回答依据。

### 局限与挑战

- **检索质量瓶颈**：若检索器未能召回关键证据，即使生成模型再强也无法给出正确答案。
- **分块策略敏感**：不合理的分块可能割裂语义完整性，导致检索到的片段缺乏自包含性。
- **上下文窗口限制**：检索过多内容可能超出模型上下文长度，或引入"迷失在中间"现象。
- **计算成本**：嵌入生成与向量检索引入额外延迟；高质量嵌入模型和重排序器增加部署成本。


## 5. 常见变体

- **朴素 RAG（Naive RAG）**：最简单的"检索→拼接→生成"流程，适用于快速原型验证。
- **高级 RAG（Advanced RAG）**：在检索前后加入查询改写、重排序、混合检索等优化步骤。
- **混合检索**：结合稀疏检索（如 BM25，擅长精确术语匹配）与稠密检索（擅长语义匹配），适用于法律、技术手册等既需术语精确又需语义理解的场景。
- **GraphRAG**：利用知识图谱进行关系感知检索，适合多跳推理和实体关联查询。


## 6. 典型应用场景

- **企业知识库问答**：接入内部制度、产品手册、FAQ，构建员工自助问答系统。
- **客户支持**：客服机器人基于最新产品文档和故障排除指南回答用户问题。
- **法律与合规研究**：检索判例、法规、合同条款，辅助法律专业人员查找先例。
- **医疗与科研**：基于医学文献或临床指南提供有证据支撑的参考信息。

- [ ] 生成提示中包含"仅依据上下文回答"的约束
- [ ] 已设计引用返回机制以支持可验证性
