# 向量存储与相似度检索实践

## 向量存储的职责

向量存储（VectorStore）负责持久化文档向量，并提供基于向量相似度的检索能力。在 Spring AI 中，VectorStore 是一个接口，不同实现对应不同的后端存储。

## SimpleVectorStore 的特点

SimpleVectorStore 是 Spring AI 提供的内存向量存储实现，特点如下：

- 数据保存在 JVM 内存中，应用重启后丢失。
- 无需额外部署数据库，适合开发调试和小规模数据。
- 添加文档时会调用 EmbeddingModel 完成向量化，因此会产生相应的 API 调用。
- 不支持按元数据做复杂过滤。

## 生产环境的替代方案

当数据量增大或需要持久化时，可以换用其他 VectorStore 实现，例如基于 PostgreSQL 的 PGVector、基于 Redis 的 RedisVectorStore、Elasticsearch 等。Spring AI 对这些后端都提供了适配，切换时主要修改依赖和配置，检索 API 保持一致。

## 相似度度量方式

常见的向量相似度度量包括：

- **余弦相似度**：衡量两个向量方向的夹角，最常用。
- **欧氏距离**：衡量向量之间的直线距离。
- **点积**：在向量归一化后与余弦相似度等价。

不同 VectorStore 支持的度量方式可能不同，选型时需要确认。

## 文档切分策略

检索效果不仅取决于模型，也与文档切分方式密切相关。切分过大会引入无关内容，切分过小会丢失上下文。常见做法是按语义段落切分，并设置适当的重叠窗口（overlap），在片段之间保留一定的上下文连续性。Spring AI 提供了 TokenTextSplitter 等工具辅助完成切分。
